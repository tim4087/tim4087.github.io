Захотел себе блог на трёх языках — без WordPress, без базы данных и без ежемесячной платы за хостинг. Рассказываю, как всё устроено под капотом: статический генератор Jekyll, переводы интерфейса через один YAML-файл и поиск по постам, который работает целиком в браузере.

<!--more-->

## Почему статика

Обычный сайт на WordPress — это сервер, который при каждом заходе читателя собирает страницу заново: скрипт лезет в базу, клеит HTML, отдаёт. Статический блог работает иначе: **все страницы собираются один раз** (при публикации), а читателю отдаются готовые файлы. Преимущества:

- хостинг бесплатный (GitHub Pages), сайт нечем взломать — нет ни базы, ни серверного кода;
- скорость: отдаются просто файлы, быстрее физически некуда;
- тексты живут в git — вся история изменений постов сохраняется.

Собирает всё **Jekyll** — генератор статических сайтов на Ruby. Тот самый, на котором работает GitHub Pages.

## Конвейер: как .md превращается в .html

Самое частое заблуждение: «я думал, там md-файлы, а ссылка — на html». Оба варианта верны! Вы пишете **Markdown**, Jekyll на сборке делает **HTML**:

```
_posts/2026-11-13-privet-mir.md      ← вы пишете это
        ↓  jekyll build
_site/2026/11/13/privet-mir.html     ← читатель получает это
```

Внутри каждого `.md` — «front matter», шапка между двумя `---`:

```yaml
---
layout: post
title: "Привет, мир!"
lang: ru
---
```

Дальше — обычный Markdown. Jekyll прогоняет его через конвертер (kramdown), оборачивает лейаутом и кладёт результат в `_site/` по папкам-датам. Вы никогда не пишете HTML руками — только Markdown и иногда чуть-чуть Liquid.

## Три языка без плагинов

Для мультиязычности не понадобилось ни одного стороннего плагина. Схема:

1. **Каждая страница и пост знают свой язык** — поле `lang` во front matter. Для забывчивых в `_config.yml` есть дефолты: всё в `_posts/` считается английским, если не указано иное.
2. **Переводы интерфейса лежат в одном файле** `_data/i18n.yml`:

```yaml
ru:
  about: "обо мне"
  recent_posts: "НОВЫЕ ЗАПИСИ"
es:
  about: "sobre mí"
```

3. **Шаблоны читают переводы по текущему языку**: `{% assign t = site.data.i18n[lang] %}` → `{{ t.about }}`.
4. **Каждая главная показывает только свои посты**: `{% assign lang_posts = site.posts | where: "lang", lang %}`. Русский пост не утонет в английской ленте, потому что в неё просто не попадёт.
5. Переключатель **en / ru / es** в шапке — это просто три ссылки на `/`, `/ru/` и `/es/` с подсветкой активного.

Пост на трёх языках — это три файла: `slug.md` (EN), `slug-ru.md`, `slug-es.md`. Мне лень было делать это руками, поэтому скрипт `new-post.sh "Заголовок" all` создаёт все три заготовки разом.

## Поиск без сервера

На статическом сайте негде «спросить базу» — и не нужно. Схема в четыре шага:

1. При сборке Jekyll генерирует **`/search.json`** — файл со всеми постами (заголовок, URL, язык, полный текст). Одна страница Liquid-шаблона, ноль кода на сервере.
2. В шапке — кнопка-лупа (и бонусом **Ctrl+K**).
3. По нажатию Enter JavaScript **скачивает `search.json` один раз** и ищет в браузере: сначала совпадения по заголовкам, ниже — по полному тексту с подсветкой найденного слова.
4. Окно — модальное, по центру, с затемнением. Всё уже в духе 2026-го, кроме веса страницы: она не тяжелеет ни на грамм, пока ты не открыл поиск.

## Структура проекта

| Путь | Что там |
|---|---|
| `_posts/` | посты (Markdown) |
| `_layouts/` | каркасы страниц: default → home / post / page |
| `_includes/` | кирпичики: шапка, подвал, поиск, картинки |
| `_data/i18n.yml` | переводы интерфейса |
| `_sass/` | стили (Sass → один CSS) |
| `search.json` | индекс для поиска |
| `ru/`, `es/` | главные и about других языков |
| `.github/workflows/` | автосборка и деплой на GitHub Pages |

## Деплой

Запушил в GitHub → Actions сам собирает сайт тем же Jekyll и публикует на GitHub Pages. От «сохранил файл» до «видно в интернете» — около двух минут.
